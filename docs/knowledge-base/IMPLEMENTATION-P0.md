# 知识库 P0 实施说明

## 入口与导航

在现有 DSH Web GUI 侧边栏增加「知识库」入口。入口打开知识库独立视图；关闭后恢复原会话，不改变会话身份。浏览器返回与入口关闭使用同一返回目标。

## 首期视图

- 知识浏览：列出已导入文档和可检索片段；支持关键词搜索与详情查看。
- Raw 收件箱：用户将大量原始文档直接放入 `knowledge/raw/`；界面显示新文件、大小、修改时间、格式和处理状态。
- 处理队列：用户逐项或批量点击“处理 raw 文档”，服务端校验、归档到 imported、写入 manifest 并使其可检索；处理前展示文件清单，失败项保留在 raw 并显示原因。
- 条目/文档详情：显示来源、状态、导入时间、路径和原文。
- 概览：显示文档数量、条目数量和索引状态。

本次不实现自动候选条目生成、会话定义写入、KG 编辑、清洁合并；它们按 `PLAN.md` 的后续阶段保留。

## 数据来源与所有权

- Raw 收件箱：`knowledge/raw/` 是用户直接投放外部文件的 Git 跟踪目录；其内容是尚未处理的原件，不参与 agent 检索。
- 已处理真源：`knowledge/documents/imported/` 与 `knowledge/documents/manifests/`，Git 跟踪。成功处理后 raw 原件按相同相对路径移动至 imported，并生成 manifest。
- 首期支持 UTF-8 `.md` 与 `.txt`；不支持或超过限制的文件留在 raw，且在界面明确报告。
- 派生索引：`.dsh/storages/knowledge-base/`，可重建、不进入 Git。
- 服务端插件负责文件访问、导入、索引和 agent 工具；客户端只通过本机 Web 路由访问数据。
- 导入材料保持 `imported` 来源性质，不自动生成 `verified` 语义定义。

## Agent 工具

- `kb_search`：按 query 搜索已导入文档，返回文档 ID、标题、片段、来源和状态。
- `kb_get`：按 document ID 读取已导入文档的完整文本和来源元数据。

两者均为只读工具，仅服务于语义理解，不替代技能库执行。

## 验证

1. 构建 host/client bundle 并确认 profile 依赖已链接。
2. 启动或复用现有 `http://127.0.0.1:3080`，确认侧边栏入口和知识库落地页。
3. 将多份 `.md` / `.txt` 放入 `knowledge/raw/`，确认界面识别待处理文件。
4. 处理一份或多份 raw 文件，确认原件移至 imported、manifest 和统计出现；不支持文件与处理失败文件仍保留在 raw。
5. 在 UI 搜索并打开详情。
5. 从真实会话进入知识库再关闭，确认返回原会话。
6. 通过 agent 工具执行 `kb_search` / `kb_get`，确认返回来源和原文。
